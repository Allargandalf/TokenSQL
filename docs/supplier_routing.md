# 供应商路由与报价差异读取契约

更新：2026-10-29。适用 v2.4，实施顺序见 plan.md，验收证据见 progress.md。

## 供应商档案

每个 supplier_id 对应一个档案；source_scope 表示同一供应商的报价单系列。档案保存 model_mappings、rules、default_prompt；sources 保存系列覆盖。映射包含 raw_name、model_id、supplier_model_id、aliases、enabled 和 evidence；规则包含 kind、text、enabled 和 evidence。

GET /api/workspace/suppliers/{supplier_id}/profile 返回 revision、当前内容与确认来源，source_scope 查询参数返回 effective 视图。PUT 同路径携带 expected_revision 保存人工编辑。模型映射指向目录中的 canonical model_id；供应商报价确认会在同事务创建缺失模型，再记录已确认映射。

任务仅加载当前供应商的通用档案和本系列的覆盖规则。已确认的补答和审核修订更新档案；界面可将说明设为仅本期有效。导入 Prompt 在勾选记为默认后成为该系列的默认 Prompt。全局 agent.md 保存应用规则和档案加载说明。

revision 用于人工编辑并发检查；effective_fingerprint 根据实际业务含义生成。证据来源和更新时间独立保存，同一含义的重复确认继续复用解析结果。

## 会话与长期理解

sessions.json 保存 supplier_id 与默认 conversation_id 的关联。选供应商时打开默认对话，并恢复该对话的导入、等待补答和最近结果。开启新一轮对话时携带档案与近期任务摘要；会话历史由 OpenCode 保存，档案承接长期含义。

官网补价继续使用独立查询对话。供应商之间分别使用自己的会话和档案。

POST /api/workspace/agent/suppliers/{supplier_id}/session 携带 source_scope 和 new_round，返回默认会话、当前会话任务、最近供应商结果、档案与上下文用量。开启新一轮后，业务理解仍由同一供应商档案提供。

## 已确认来源基准

每个 supplier_id/source_scope 对应最近确认的来源基准：归档文件引用、工作表结构快照、已确认候选结果、解析版本、解释指纹和确认任务。原件沿用 data/；基准作为轻量读取索引维护。

表格快照保留工作表、单元格原值和类型、数值格式、公式及缓存值、合并区域、备注。对齐依据表格内容和上下文，来源位置用于定位证据。调序后仍可识别相同内容。

比较结果区分新增、修改、删除、位置调整和展示变化。单位、百分比、币种格式及表头脚注变化带出相关数据；公式依赖变化连同结果区域进入变化包。合并表头、多行模型和无法唯一对齐的区域一起提供上下文。纯值XLS支持展示变化复用；包含公式且BIFF公式信息不可完整读取的XLS，在文件变动时采用整表理解。

## 变化理解与数据库对账

沿用当前档案和 Prompt 时，相同内容及展示变化复用已确认解释，模型调用为零。少量变化将变化区域、相关旧内容、表头、说明和相邻行交给 OpenCode。档案含义或本期 Prompt 变化时更新解释；界面提供整表重新理解。

合并复用结果与本期重新理解的结果，得到完整的本期来源候选，再与最新数据库对账。增量更新、完整替换、人工编辑和确认沿用 supplier_updates.md 的流程。确认后更新最新基准和档案，取消后归还文件。

审核展示来源表格对比、复用与重新理解数量，以及数据库的新增、修改、删除、不变、待确认分组。性能记录分别包含读取比较、模型与总耗时、模型调用次数、实际可得 token 或输入字数、补答次数和会话上下文用量。

导入入口新增 full_reparse（整表重新理解）、persist_profile（确认后保存长期含义）、remember_prompt（记为默认导入要求）。任务返回 source_comparison、reading_plan、metrics 和 context_usage。semantic_requests按SDK语义请求计数，一次请求可能包含多个LLM步骤；提交文字量不包括历史及工具读表内容。可得时另列整个任务的输入/输出/缓存token，只有末次回复统计时明确标注。

确认后每个系列保留最新完整表格对比，旧任务保留候选、统计和归档引用；等待及确认恢复所需缓存单独保留到流程完成。

## 验收

使用隔离库验证供应商与来源隔离、重启恢复、重复和展示变化零调用、小幅变动上下文、合并表头/公式/单位变化、全表与差异结果等价、当前库人工修改后的重新对账。真实模型测量与脚本化 SDK 测量分别记录；业务文件全量双库核对继续列入后续计划。
